Detailed Description

The process-wide worker budget behind –threads as a hard global cap (Stage 2B #19).

The app sets the cap once per process (a route job sets it from its thread count); 0 means no cap was set and every stage keeps its historical behaviour. The portfolio's variant workers are the primary workers: route_portfolio registers how many are alive, and secondary stages (zone refill's per-layer tasks) may only add threads with what the cap leaves free, so the process never runs more concurrent workers than the cap. The main thread and the live-log writer are not workers; the documented OS-level thread peak is cap + 2.
